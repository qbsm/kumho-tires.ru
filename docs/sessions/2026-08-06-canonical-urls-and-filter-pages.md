# Канонические адреса без слеша и человечные адреса фильтра каталога

## Задача

Убрать хвостовой слеш и лишние 301 по всему сайту, сделать человечные адреса фильтра каталога вместо `?season=…&width=…`. Дополнительно: блок-переход на конфигуратор в каталоге, обложка каталога высотой как на `/about`, SEO/GEO-проверка новых страниц.

## Хвостовой слеш: каждая внутренняя ссылка шла через редирект

`UrlExtension::url()` дописывал `/` в конец пути, а `TrailingSlashMiddleware` этот слеш срезает 301-м редиректом. То есть *все* внутренние ссылки сайта (меню, карточки, футер, хлебные крошки) вели на редирект: лишний хоп для пользователя и размазанный вес ссылок для поисковика.

Слеш дописывается только для путей без расширения — файлы (`.pdf`, `.jpg`) остаются как есть. Каноническим стал адрес без слеша: `/contacts` — 200, `/contacts/` — 301 на него.

Смоук-тест `tests/smoke/smoke.js` проверял обратное поведение — переписан на канонический адрес. Заодно чек `/en/` стал зависеть от языков в `global.json`: на одноязычном деплойменте (kumho) ожидается 404, а не 200 — раньше тест из baseline падал здесь всегда.

## Человечные адреса фильтра

Появились три формы адреса в каталоге:

- `/tires/summer` — сезон (`summer`, `allseason`, `winter`, `studded`);
- `/tires/205-55-r16` — типоразмер;
- `/tires/summer/205-55-r16` — сезон и типоразмер вместе.

Разбор адреса — в `PageAction::parseFilterParams()`, конфигурация в `config/project.php` (`collections.tires.filters`): словарь сезонов, регулярка типоразмера и границы каталога `size_ranges`. За границами (`/tires/summer/999-99-r99`) — 404, а не пустой фильтр: иначе на сайте появилось бы бесконечное множество мусорных адресов.

Пресет уезжает в шаблон через `filter_preset` → `.js-filter-preset` с data-атрибутами; `assets/js/sections/tires.js` читает сначала dataset, потом query-параметры — старые ссылки вида `?season=allseason&width=195` продолжают работать.

Кнопка «Перейти в каталог» в конфигураторе теперь строит человечный адрес, когда он существует (сезон и/или полный типоразмер); частичный размер по-прежнему уходит параметрами.

### Что сделано, чтобы адреса не размножили дубли

- **Сезонные страницы индексируются**, комбинации с типоразмером — `X-Robots-Tag: noindex, follow` (их сотни, вес по ссылкам на модели передаётся).
- **Свой title/description и h1** у каждой сезонной страницы — иначе четыре адреса делили заголовок с общим каталогом. Падежи в description берутся из конфига (`genitive`), h1 — оттуда же.
- **Canonical** страницы указывают на себя (`base.twig` строит его из `route_params`).
- **Хлебные крошки**: Главная → Шины → Летние → 205/55 R16.
- **Sitemap**: четыре сезонные страницы добавлены через новый `sitemap_extra_paths` в `config/project.php`.

## Попутно исправлено в ядре

`buildEntityBreadcrumb()` отдавал последнему элементу URL `/<slug>/` — без раздела, то есть 404: на `/tires/ps72` третья крошка вела на `/ps72/`. Теперь `/tires/ps72`, и все URL в крошках — канонические, без слеша. Ошибка платформенная, есть во всех деплойментах.

## Блок-переход на конфигуратор в каталоге

На `/tires` между модельным рядом и лонгридом добавлен блок со ссылкой на `/podbor`. Новая секция `cta` (`templates/sections/cta.twig` + `assets/css/sections/cta.css`) — JSON-управляемая: заголовок, описание, кнопка. Оформление — из словаря сайта: светлый бэнд `#f8f9fb` (как у конфигуратора на главной и у partners), скошенная красная метка `heading-accent`, штатная кнопка `button-sm button-3`.

Обложка каталога поднята до высоты обложки `/about` (52.5rem) — правило в `assets/css/pages/about.css` теперь общее для двух страниц.
