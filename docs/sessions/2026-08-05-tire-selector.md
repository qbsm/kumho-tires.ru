# Конфигуратор подбора шин (/podbor)

## Задача

Сделать на базе quiz'а из legacy-проектов iSmart конфигуратор подбора шин Kumho. Без отправки заявки: результат подбора ведёт в каталог.

## Что взято из legacy-quiz

Референс — `sollers-nevastar.ru-quiz/dev/src/components/quiz/` (та же реализация в ~12 проектах: solaris-krylatskoe, service.vlv-tul, promo.soueast-mbb и др.). Оттуда взята механика: пошаговые экраны, выбор карточкой с автопереходом, прогресс-бар, кнопка «Назад».

Не переносилось: jQuery, `console.log`-отладка, конкатенация ответов в скрытое поле формы, разметка `card/card__item` — переложено на конвенцию движка (`section__item`/`section__subitem`, vanilla ES-модуль с `onReady`, штатный `components/card-tire.twig`).

## Как устроено

Секция `tire-selector` — JSON-управляемая: шаги, варианты, иконки и настройки результата описаны в данных страницы, шаблон не знает про конкретный контент. Стоит на двух страницах: `/podbor` (лимит выдачи 6) и на главной между модельным рядом и новостями (лимит 3).

Шаги: тип автомобиля → сезон → приоритет → размер → результат.

На шагах-вариантах включён мультивыбор (`"multiple": true` у шага). Внутри шага значения работают по ИЛИ, между шагами — по И; при мультивыборе появляется кнопка «Далее», заблокированная до первого выбора. Флаг снимается по шагам, если где-то нужен одиночный выбор с автопереходом.

Каталог (36 видимых моделей) рендерится в результат server-side с data-атрибутами, фильтрация — на клиенте:

- `vehicle` и `season` — жёсткий фильтр;
- `priority` — мягкий, поднимает подходящие модели выше в выдаче (не отсекает);
- размер — необязательный, селекты заполняются из реальных `sizes` уже отфильтрованного пула и сужают друг друга.

Сезон в шаге разделён на «шипованные» и «нешипованные»: у шипованных моделей в данных стоят оба токена (`winter` + `studded`), поэтому «нешипованные» — это `winter && !studded`.

## Данные

В `filter` каждой из 37 моделей добавлены `vehicle` (passenger/suv/commercial) и `priority` (comfort/handling/economy/offroad). Классификация — по `desc.short` самих моделей, где тип техники назван прямо («для внедорожников и пикапов», «для лёгкого коммерческого транспорта»), приоритет — по семантике серии (Ecowing → экономичность, ECSTA → управляемость, CRUGEN/WinterCraft → комфорт, Road Venture/PorTran → проходимость и нагрузка). У WI32 приоритета нет намеренно — описание не даёт основания ни для одного из четырёх.

## Переход в каталог

Кнопка «Перейти в каталог» собирает ссылку `/tires?season=…&width=…&profile=…&diameter=…`. В `sections/tires.js` добавлено чтение этих query-параметров при инициализации, поэтому фильтр каталога открывается уже выставленным. Сезон маппится в токены каталога: `friction → winter`, `all-season → allseason`. Фильтр каталога держит только один сезон, поэтому при мультивыборе двух и более сезонов параметр не передаётся — размеры едут в любом случае.

## Оформление

Типографика взята с сайта: вопросы шагов — `h4 heading font-2 weight-700 uppercase`, пояснения — `.desc`, карточки вариантов повторяют структуру `card-action` (иконка → uppercase-заголовок → акцентная линия → описание), радиусы 1.5 rem как у карточек, кнопки — штатные `.button` (`button-3` и `outline-color-2`) с доведёнными состояниями: лифт на hover, красная тень у основной, нейтральный серый в disabled.

Рамки, радиусы и кнопки не изобретались заново, а взяты с сайта: карточка варианта повторяет `card-tire` (0.1rem рамка, радиус 1/2 rem, акцент на hover, переход только по `border-color`/`background`), панель — контейнер фильтра, поля размера — его селекты (высота 3.2 rem, радиус 0.75 rem), кнопки остались штатными `.button` со своим радиусом и сдвигом стрелки. Своего в кнопках только `disabled`, которого в базовых вариантах нет.

Движения на hover нет намеренно: ни сдвигов, ни теней, ни изменения размеров — на сайте карточки меняют только цвет рамки. Выбор помечается круглым чек-бейджем: при мультивыборе иначе неочевидно, что вариантов можно взять несколько; активная карточка дополнительно получает лёгкую подложку, чтобы отличаться от hover.

Иконки шагов сезонов — штатные `icon-season-*.svg`. Для типа кузова и приоритета добавлены `icon-sel-*.svg` в той же геометрии, что и сезонные: сплошные фигуры толщиной 2 на сетке 24, прямые торцы, «полые» кольца (колёса, обод руля). Подключаются через CSS-маску, поэтому перекрашиваются в акцент при выборе.

## Проверено

Локально (Valet, `kumho-tires.ru.test`), прогон Playwright'ом при 1440 и 390 px:

- кроссовер + зима нешипованная + комфорт → WI51, WS51, WS71 (шипованные WI32/WS31 не попадают);
- легковой + шипы → WI32; коммерческий + лето + экономичность → KC53;
- зависимые селекты размера: после 235 и R18 профили сузились до 40–65;
- переход в каталог с `?season=winter&width=235&diameter=18` — фильтр каталога выставлен, показаны зимние модели;
- «Назад» и «Подобрать заново» возвращают шаг и сбрасывают выбор;
- ошибок в консоли нет (падают только запросы Метрики на .test — внешние).

Гейты: eslint, stylelint, prettier, phpstan, phpunit (42), vitest (21), validate-json — зелёные.
